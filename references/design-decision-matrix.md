# 载体 → 设计默认 决策矩阵

**这张表是工作流第四步（定引擎、编译规格）的查表依据。** 载体决定引擎、比例、文字层级和构图骨架；画风和配色由第三步的《设计方案》定，本表只在方案缺位时兜底。

**一句话用法**：先认载体（公众号封面 / 信息图 / 小红书组图 / 文章配图），落到对应行，先看「引擎」列定走 render.py 版式还是 gen.py 插画，再把那一行的构图默认抄进规格文件，画风配色两列填《设计方案》里定好的值。

---

## 先记三条全局铁律（所有载体共用）

**第一条：设计方案先行，风格配色不查表、查方案。**

本表管「结构性默认」：引擎、比例、文字层级、构图骨架、坑。画风和色板是「表达性决策」，一律出自《设计方案》（用户指定 > 配套文件推断 > 风格库默认），本表不写死任何画风。方案还没出就来查这张表，说明跳步了，回第三步。

**第二条：逐字精确的文字只走版式引擎。**

封面大标题、信息图、金句卡、流程标签，这类一个字都不能错的活交给 render.py 加 HTML 模板，浏览器渲染零变形。扩散模型写字必崩，中文尤其崩，别硬塞。

**第三条：插画走 API 三个物理出图桶，版式走 HTML 模板。比例是「意图」不是「像素」。**

插画类走 OpenAI 兼容的 gpt-image 类模型，实际只吐三种分辨率，所有比例自动映射到最近的桶：

| 出图桶 | 像素 | 吃掉哪些常见比例 |
|---|---|---|
| 方 | 1024×1024 | 1:1 |
| 横 | 1536×1024 | 16:9、4:3、3:2、5:4、21:9 |
| 竖 | 1024×1536 | 3:4、9:16、2:3、4:5 |

**所以下面每行的「推荐比例」给的是构图意图，括号里标它实际落进哪个桶。** 想要 2.35:1 的电影封面，比例传 21:9，API 给你的还是 1536×1024 的横图，构图时按宽幅排，别指望真出 2.35:1 的扁条（脚本只收上表列出的比例写法）。需要精确的窄幅版式、逐字精确的文字（标准公众号封面、长条信息图），那是版式图，走无 key 引擎 render.py 截 `templates/*-clean.html`，文字零变形、尺寸随便定，不受三桶限制。

|---|---|---|---|---|---|---|

| **小红书组图** | 插画 → gen.py；纯文字卡可走版式 render.py | 竖 3:4（竖桶 1024×1536），首图同比例 | 按《设计方案》；封面图冲击力拉满、内容图降一档保可读，全组同一色板 | 封面 sparse 大字钩子（≤10 字）；内容图 balanced，一个小标题 + 2-4 个要点；要逐字精确的文字卡走版式引擎 | 首图 hero 钩子（方案定的主体当主角）→ 内容图每张一个点 → 尾图 CTA；**全组锚住首图的主体和色板，否则张张漂移** | 小红书安全区：顶部右角（点赞分享按钮区）、底部 10%（标题栏遮挡）别压关键信息和文字；组图不锚首图会风格跳；API 出多字必崩，文字密的卡片改走 HTML 截图；单组别超 6 张（成本护栏） |
| **文章正文配图（章节图）** | 插画 → gen.py | 16:9 宽幅（横桶 1536×1024） | 按《设计方案》；全文各章同一色板，可微调色温区分章节 | none 或极少字（≤30%）：靠画面和角色动作叙事，不当字幕板 | 单场景，主体 + 一个核心道具演出本章动作，16:9 复现场景 | 章节图最容易退化成「配字幕的装饰图」，靠主体动作把本章讲清，做到看图懂；文字越少越稳，想说的话留给正文不留给图 |

## 文章配图再展开（高频，多给几类）

文章配图不止章节图一种，按用途分四类。画面型走插画引擎，逐字精确的卡片型走版式引擎，按这个分。

| 配图子类 | 引擎 | 推荐比例（实际桶） | 文字层级 | 构图模板 | 用在哪 | 典型坑 |
|---|---|---|---|---|---|---|
| **章节场景图** | 插画 → gen.py | 16:9（横桶） | none / ≤30% | 单场景，主体 + 核心道具演出本章动作 | 每个 `##` 章节标题下方，喂完读率 | 退化成装饰；靠主体动作做到看图懂本章 |
| **概念对比图** | 插画 → gen.py | 16:9（横桶）或 1:1（方桶） | 少字，左右各一个标签 | 左右对置分区，中间留白分割，两侧各一个主体/道具 | 讲「A 不行 B 行」「以前 vs 现在」 | 左右构图要平衡，对比物要一眼分清；标签字少，精确文字交给版式引擎 |
| **数据/金句卡** | 版式 → render.py `cover-clean.html` | 1:1（HTML 自定尺寸） | title 级一句金句大字，可带数字 | 单焦点居中，金句/数字用大字重排版，大量留白，细线点缀 | 文中要被截图转发的那句狠话 | 数字别让模型乱编，HTML 里写死即可零变形；金句 ≤14 字，留白别填满 |
| **流程/步骤图** | 版式 → render.py `infographic-clean.html` | 21:9 宽板或竖 3:4（用模板现成板） | 少字，每步一个短标签 | 3-6 个节点连线，方向感（左→右或上→下），极简线性图标 | 讲操作流程、工作流、几步搞定 | 节点超 6 个必乱；步骤标签压成 2-4 字；箭头方向别拧 |

## 查表流程（第四步用这个）

1. **认载体**：从 brief 的「载体」维度读出来。认不准就按主题猜，封面感（一句话钩子）走封面，要点多走信息图，种草向走小红书组图，给文章喂图走文章配图。
2. **定引擎**：照载体的「引擎」列分流，逐字精确的版式（封面、信息图、金句卡、流程图）走 render.py 的 `*-clean.html`，画面叙事的插画（章节图、小红书组图、对比图）走 gen.py。拿不准就看文字密不密：文字一多一精确就走版式。
3. **抄默认**：落到对应行，把结构性默认（引擎 / 比例 / 文字层级 / 构图 / 坑）抄进规格文件；画风配色两格填《设计方案》定好的值。
4. **填偏离理由**：用户明确指定的维度覆盖默认，并写一句为什么偏离。没指定的全照默认，不反问。
5. **单轮自检**（不递归）：照下面 checklist 过一遍，过不了的就地修，修完不再回头死循环。

### 单轮 checklist

- [ ] 引擎选对了：版式走 render.py `*-clean.html`，插画走 gen.py，没用插画引擎硬出精确长文
- [ ] 比例选了；插画类标清落进哪个桶（方/横/竖）按桶形状排，版式类尺寸 HTML 自定即可
- [ ] 《设计方案》在场：画风、色板、场景都有值且带来源等级，没有跳过第三步
- [ ] 配色 ≤3 个可见色系，hex 写死进 prompt 或模板，没让模型自己挑色
- [ ] 文字层级跟载体匹配（封面 title-only、信息图 text-rich、章节图 none/极少），且字数在该载体上限内
- [ ] 逐字精确的文字走版式 HTML 截图零变形，没硬塞给 gen.py（gpt-image 类模型多字必崩）
- [ ] 小红书组图：全组锚住首图的主体和色板，安全区没压关键信息
- [ ] 插画靠主体动作把意思演清楚，画面用的是配套文件里的真实意象；版式靠结构和留白把信息讲清
- [ ] 没超成本护栏（单组张数上限、回炉最多 1 轮）

## 各载体默认速记（懒人版）

记不住主表就记这四句，够用：

**公众号封面**：版式 `cover-clean.html` + 宽幅 + 单焦点大留白 + ≤12 字大标题 + 一个克制强调色（色值按设计方案）。
**信息图**：版式 `infographic-clean.html` + 竖/方 + 模块化网格 + 三级文字 + ≤6 块每块一句话，文字零变形。
**小红书组图**：插画 + 竖桶 + 首图钩子拉满 + 全组锚首图 + 避开顶右和底部安全区。
**文章配图**：插画 + 横桶 16:9 + 每章一个主体场景 + 文字越少越稳 + 看图懂本章；金句卡/流程图改走版式引擎。
