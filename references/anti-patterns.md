# 反 AI 体检清单 + 能力圈声明

这个产品自己就是 AI 生图工具，反 AI 是让吐出来的图有明确的设计意图，跳出任何扩散模型随手吐的均值图。

文字稿那套反 AI 味的逻辑搬过来一样成立：**你越是 AI 高手，做出来的东西越不能让人一眼看出是 AI 做的。** 通用 AI 生图的问题跟通用 AI 写作一个病根，都在往中间值塌缩。生图塌缩成完美对称加塑料高光加居中构图加谁都画过的烂隐喻。heige-image 靠《设计方案》跳出均值：画风、色板、场景每项都有明确决策和理由，模型只负责执行，无权自由发挥。体检清单就是把塌缩点一条条拎出来，出图前压住，出图后回查。

---

## 一、反 AI 体检清单

分两段过。**出图前过 prompt，出图后过成品。** 两段都过完才算交付。

### 出图前体检（过 prompt 规格文件，落 prompts/NN-主题.md 时就查）

每条都是问句，答不上来或者答案踩雷就回去改 prompt，别先出图浪费额度。

**1. 隐喻有没有撞烂梗。**
灯泡代表创意、齿轮代表系统、发光大脑代表 AI、向上箭头代表增长、握手代表合作，这些是扩散模型训练集里被喂烂的视觉口水话，出来就是一眼 AI。解法在工作流第一步：**优先画配套文件里真实出现的意象**。文章写了「工资被抽走一截」就画抽走的动作，写了「跑步机上原地跑」就画跑步机。具体到能截图，抽象到只剩符号就是 AI 味。

**2. 构图干不干净。**
画面堆满杂物、元素挤到边、背景塞复杂场景，是 AI 生图的另一种崩法。prompt 里主动写 clean background、minimal、generous negative space，主体放居中或黄金分割点，别让模型把画面填满。设计方案里「场景与构图」写的是什么，画面里就只有什么。

**3. 配色有没有滑进投降色。**
莫兰迪灰调和蓝紫渐变发光是 AI 生图两大投降色，谁的图都长一个样。解法：**色板 hex 出自《设计方案》且写死进 prompt**，别让模型自己挑色。方案色板来自品牌色或配套文件推断时尤其要锁死，滑色等于方案白做。

**4. 质感是不是又是默认渲染。**
那种圆润反光的 C4D 塑料感、强高光、磨皮干净到没有一粒灰，是 AI 生图的出厂设置。解法：设计方案选定的风格词条里有明确的材质词和光感词（风格库每条都列了），整段抄进 prompt，负向里带上该风格的禁忌项。质感词写不足，模型就滑回出厂设置。

**5. 文字层级有没有越界。**
插画和概念图里文字占比压在 30% 以内，靠画面叙事。文字一多就暴露 API 生图的死穴（见下面能力圈），而且容易变成那种贴满标语的 AI 海报味。要精确排版的版式图这条管不住，那种活走 render.py 版式引擎，别硬塞给 API。

**6. 这张图换个主题还成不成立。**
prompt 写得太通用，换个标题照样能套，说明它没扎进这一篇的具体冲突，就是一张可替换的库存图。好的规格是这张只服务这一篇，invariant 清单写得出哪些必须锁死。

### 出图后体检（拿到成品图，贴出去之前查）

成品图肉眼过一遍，下面任意一条中招就回炉。**回炉最多 1 轮**，1 轮还不行就降级处理（换主体重写 prompt，或者老实承认这张不该用 API 做）。

**7. 手、字、对称物有没有崩。**
手指数量、文字拼写（尤其中文，扩散模型基本写不对）、左右本该对称的物件（耳机、眼睛、四肢），这三处是 AI 生图崩坏重灾区。崩了直接废，别将就贴。

**8. 有没有那股通用 AI 油光。**
说不清哪不对但就是觉得假、觉得腻、觉得在哪见过，多半是那股塑料高光加均值构图又回来了。相信这个直觉，它跟读文字时那句「这读着像机器写的」是同一种警报。

**9. 方案符合性过不过。**
盖掉一切上下文，拿成品对照《设计方案》逐项查：色板对不对、画风对不对、场景对不对、文字层级有没有越界。成品跟方案对不上，等于设计总监白干，模型自由发挥的图就是均值图。逐项判法见 `design-director.md` 验收段。

**10. 情绪到没到位。**
方案里定的情绪调子（治愈 / 专业 / 锐利 / 轻松），看图的人接不接得到。画面只是好看、只是把字面意思画出来，情绪没传达到，就退化成普通配图了。这条最难量化，判法是把图给一个没看过方案的人看一眼，问他什么感觉。

### 一句话自检

出图前问：**这 prompt 是不是谁都能写出来？** 出图后问：**这张图对得上设计方案吗？** 两个都答得硬气，才算过检。

## 二、能力圈声明

诚实划边界。不阉割能做的，不夸大做不到的。三个脚本都已落地，下面说清楚各自能做什么、需要什么、不做什么。

### 现在能做什么

**插画 / 概念图 / 示意图，走 API 引擎 gen.py。**

- 走 OpenAI 兼容的 gpt-image 类 API，自己配 base_url + key（官方、Azure、各家中转都行，国内可选 gptx.cc 这个渠道）。
- 画风按《设计方案》走，风格库十个词条起步，用户点名库外风格照做。
- 适合的活：章节配图、16:9 总结图、概念图、示意图、不需要精确文字的画面。

**版式图（封面 / 信息图 / 卡片 / 流程图），走无 key 引擎 render.py。**

- 选 `templates/*-clean.html` 模板→填真实数据→Playwright 截图，零 API、免费、中文一个像素不差。
- 版面气质是编辑简约（留白、网格、克制强调色），色板按设计方案填进模板 custom 色板块。
- 适合的活：要逐字精确文字的封面大标题、多级文字信息图、数据金句卡、流程步骤图。

**图生图 / 改图，走 API 引擎 edit.py。**

- 单图编辑（换背景、改元素）和多图合成（图1基底 + 图2人脸/风格参考），批量并发同 gen.py。

**三条引擎共用工作流五步**：收集配套文件、需求翻译成 7 维 brief、设计总监出《设计方案》、查决策矩阵定引擎编译规格、出图验收。每张插画先落 `prompts/NN-主题.md` 规格文件，可复现可改单变量；成本护栏只管 API 引擎（单次张数上限、回炉最多 1 轮），版式引擎免费不约束。

### 需要什么

- **API 引擎要一把能用的 key**（自己配 base_url + key，接任意 OpenAI 兼容 API，国内可选 gptx.cc 这个渠道）。没 key 前四步照跑，能交付设计方案和规格文件，就是出不了图。规格先行这个机制刚好让没 key 时也有产出。
- **版式引擎要 Playwright + chromium**（`pip install playwright && playwright install chromium`），装一次到处用，不要 API key。

### 不做什么

**别拿 API 引擎硬出精确文字版式。** 扩散模型生图本质画的是像素，排版不是它的活，文字稍长就拼错、字距乱、对不齐，中文尤其崩。封面大标题、信息图、卡片这类逐字精确的活交给 render.py 版式引擎，HTML/CSS 焊死版面，文字零变形。

**还有几条边界一并说清，免得踩坑当 bug 修：**

- **API 尺寸只有三种，别信十种比例。** API 层实际只出三种分辨率：方图 1024×1024、横图 1536×1024、竖图 1024×1536。脚本里那十种宽高比全部映射到这三种里去，写 21:9 跟写 16:9 出来的图一样大。要真正的超宽幅、要精确画幅比，走版式引擎在 CSS 里焊任意尺寸。
- **API 图里文字别指望写对。** 重申第 5 条体检，图里文字压在 30% 以内，且默认它可能拼错。需要可读、要正确的文字，走版式引擎。
- **设计总监不越权。** 用户明示的画风、配色、场景永远优先，设计总监只在缺口处补专业判断，禁止拿「更好看」推翻用户要求。

### 一句话定位

**有 key 就能按《设计方案》出插画，规格文件可复现可改；要逐字精确的版式图走无 key 的简约版式引擎，免费且文字不崩。用户说了算，没说的按配套文件推断，每个决策带理由。**
